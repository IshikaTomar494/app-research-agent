How the agent works

Search → Read documentation → Extract claims → Check evidence → Human review

The Python research agent processes app documentation, extracts structured API and MCP information, stores evidence and records errors for follow-up. The project uses an LLM-powered research workflow and Python-based processing.

Reproduce: python agent_v2.py (check the repository README for the exact configuration and commands).

Important methodology note

The V2 comparison includes manual corrections aligned with the human reference. Therefore, 93.5% is comparison agreement, not an independent second-pass accuracy measurement. The 63 unclear checks were not scored. The verification was a documentation-based desk audit, not live credential-based testing.

Where human review was needed

58 records are flagged for human review in the dataset. The separate original and supplemental review queues preserve review history.

Known evidence gap: Paygent Connect (ID 84) has no evidence attached, so its claims should remain unverified.

Comparison mismatches: Shopify authentication, Gorgias authentication, Pinterest access requirements and higgsfield access classification remain mismatches against the reference.

Some evidence entries were manually mapped and not independently validated by the automated strict-check process. Public documentation and product access policies can change.

Project limitations

  • Documentation-based research does not prove that every endpoint works with live credentials.
  • Some apps have unclear, gated or changing API access policies.
  • MCP availability can change and should be confirmed against official project documentation.
  • Human review remains necessary for uncertain claims and missing evidence.
  • The dataset's 100 successful processing statuses do not mean all 100 records are fully verified.
